# Tournament Master — نسخهٔ ۳ (v3)

اپلیکیشن فلاتر برای ساخت و مدیریت تورنمنت‌های لیگ و ناکوتی، با پشتیبانی از گروه‌بندی، صدها تیم، رمز عبور اختیاری برای هر تورنمنت، دسته‌بندی بر اساس نوع ورزش، جستجو، سکوی قهرمانی، حالت روشن/تاریک، ۸ زبان، تبلیغات AdMob، و ذخیره‌سازی محلی با SQLite.

## راهنمای کامل: از ساخت تا انتشار در گوگل پلی و کسب درآمد از تبلیغات

### ⚠️ رفع خطای Gradle (اگر روی گوشی‌تان دیده بودید) — علت دقیق پیدا شد

پکیج `google_mobile_ads` (و پیش‌تر `share_plus`) روی سیستم شما این خطا را می‌داد:
```
Could not get unknown property 'all' for configuration container for project ':google_mobile_ads'
```
**علت دقیق:** ابزار Flutter/Android شما به **Android Gradle Plugin نسخهٔ ۹ (AGP 9)** ارتقا یافته، که ساختار داخلی‌اش را عوض کرده؛ خیلی از پکیج‌ها (ازجمله همین‌ها) هنوز خودشان را با این نسخهٔ جدید هماهنگ نکرده‌اند.

**راه‌حل رسمی و مستند از خودِ فلاتر:** فایل `android/gradle.properties` را باز کنید و این دو خط را به آن اضافه کنید (اگر فایل نبود، بسازید):
```
android.newDsl=false
android.builtInKotlin=false
```
سپس:
```bash
flutter clean
flutter pub get
flutter run
```
این یک راه‌حل موقت ولی کاملاً رسمی است که خودِ تیم فلاتر برای همین دوران گذار پیشنهاد کرده. اگر باز هم مشکلی دیدید، متن دقیق خطا را برایم بفرستید.

### ⚠️ رفع کرش «Missing application ID» بعد از نصب برنامه روی گوشی

اگر برنامه با موفقیت build شد ولی بلافاصله بعد از باز شدن روی گوشی کرش کرد و در لاگ چیزی شبیه این دیدید:
```
Missing application ID. AdMob publishers should follow the instructions here...
```
یعنی هنوز شناسهٔ AdMob را به `AndroidManifest.xml` اضافه نکرده‌اید. فایل `android/app/src/main/AndroidManifest.xml` را باز کنید و این را داخل تگ `<application ...>` (همان ابتدای آن، قبل از `<activity>`) اضافه کنید:
```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-3940256099942544~3347511713"/>
```
(این شناسهٔ تستی رسمی گوگل است — برای توسعه کاملاً امن است؛ پیش از انتشار در گوگل پلی، طبق «مرحلهٔ ۵» پایین همین فایل، آن را با App ID واقعی خودتان جایگزین کنید.) سپس:
```bash
flutter clean
flutter pub get
flutter run
```

### 🛡️ ایمنی حساب AdMob — کنترل دفعات نمایش تبلیغات

برای اینکه حساب AdMob شما به‌خاطر «تبلیغات بیش‌ازحد» مسدود نشود، این سیستم‌های محافظتی در کد اضافه شدند:

- **تبلیغ هنگام ورود به برنامه (App Open Ad):** درست بعد از اسپلش‌اسکرین (نه رویش) یک‌بار نمایش داده می‌شود، و وقتی کاربر از یک برنامهٔ دیگر به این برنامه برمی‌گردد هم دوباره نشان داده می‌شود — اما **حداکثر یک‌بار در هر ۴ ساعت** (همان بازهٔ توصیه‌شدهٔ خودِ گوگل).
- **تبلیغ تمام‌صفحه (Interstitial):** بعد از ساخت هر تورنمنت جدید، و همچنین بعد از پایان یک تورنمنت (چه لیگ چه ناکوتی) نمایش داده می‌شود.
- **محدودیت مشترک:** هیچ‌کدام از تبلیغات تمام‌صفحه (چه App Open چه Interstitial) نمی‌توانند در فاصلهٔ کمتر از **۶۰ ثانیه** از همدیگر نمایش داده شوند — یعنی حتی اگر چند اتفاق پشت‌سرهم رخ دهد (مثلاً ساخت تورنمنت و بلافاصله پایان یک تورنمنت دیگر)، کاربر غرق تبلیغات نمی‌شود.
- بنر (Banner) ثابت پایین صفحهٔ Home هم مثل قبل باقی مانده (بنرها طبق قوانین گوگل هیچ محدودیت زمانی ندارند).
- سیستم رضایت تبلیغات (UMP/GDPR) هم فعال است — از منوی تنظیمات > «تنظیمات حریم خصوصی تبلیغات» قابل مدیریت است.

⚠️ **مهم:** خودتان یا دوستانتان هرگز روی تبلیغات داخل برنامه کلیک نکنید (حتی برای تست) — این کار طبق قوانین گوگل «کلیک نامعتبر» شناخته می‌شود و می‌تواند حساب AdMob را برای همیشه مسدود کند. برای تست، به‌جای کلیک، فقط تماشا کنید که تبلیغ به‌درستی نمایش داده می‌شود.

### مرحلهٔ ۱ — ساخت حساب گوگل پلی (Google Play Console)

1. به [play.google.com/console](https://play.google.com/console) بروید و با یک حساب گوگل وارد شوید.
2. هزینهٔ یک‌بارهٔ **۲۵ دلار آمریکایی** را با کارت بانکی بین‌المللی (ویزا/مسترکارت) پرداخت کنید — این هزینه فقط یک‌بار برای کل عمر حساب توسعه‌دهنده است، نه برای هر برنامه.
3. فرم اطلاعات حساب (شخصی یا سازمانی)، آدرس، و شمارهٔ تلفن را تکمیل کنید. اگر به‌عنوان فرد ثبت‌نام می‌کنید، ممکن است گوگل چند روز طول بکشد تا هویتتان را تأیید کند.

### مرحلهٔ ۲ — تغییر نام بستهٔ برنامه (Package Name / Application ID)

گوگل پلی نام‌های `com.example.*` را قبول نمی‌کند و هر برنامه باید یک شناسهٔ یکتا داشته باشد. در فایل `android/app/build.gradle` (یا `.kts`) دنبال این خط بگردید:
```
applicationId = "com.example.tournament_master"
```
و آن را به یک نام یکتا و دائمی تغییر دهید (این نام بعداً هرگز قابل تغییر نیست):
```
applicationId = "com.naweedrezayi.tournamentmaster"
```
همین مقدار از قبل در کد برنامه (`lib/screens/about_screen.dart`، متغیر `kPlayStorePackageId`) برای لینک‌های Rate/Share استفاده شده، پس با هم هماهنگ می‌مانند.

### مرحلهٔ ۳ — امضای برنامه (App Signing) برای نسخهٔ Release

برای انتشار باید یک کلید امضا (keystore) بسازید:
```bash
keytool -genkey -v -keystore ~/tournament-master-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias tournamentmaster
```
چند سؤال (رمز عبور، نام، کشور) می‌پرسد — پاسخ دهید و **رمزها و فایل keystore را جایی امن نگه دارید** (اگر گم شود، دیگر نمی‌توانید همان برنامه را آپدیت کنید).

سپس در پوشهٔ `android/` یک فایل بسازید به نام `key.properties`:
```
storePassword=<رمزی که انتخاب کردید>
keyPassword=<همان رمز یا رمز جدا>
keyAlias=tournamentmaster
storeFile=C:/Users/Naweed Rezayi/tournament-master-key.jks
```
و در `android/app/build.gradle` بخش `signingConfigs` و `buildTypes.release` را طوری تنظیم کنید که از این فایل استفاده کند (اگر نیاز به کمک دقیق با این بخش داشتید، فایل build.gradle فعلی‌تان را برایم بفرستید تا خط‌به‌خط برایتان اضافه کنم).

سپس نسخهٔ نهایی را بسازید:
```bash
flutter build appbundle --release
```
فایل خروجی در `build/app/outputs/bundle/release/app-release.aab` همان چیزی است که در گوگل پلی آپلود می‌کنید.

### مرحلهٔ ۴ — ساخت برنامه در Play Console

1. در Play Console روی **Create app** کلیک کنید.
2. نام برنامه (`Tournament Master`)، زبان پیش‌فرض، نوع (App)، و رایگان/پولی (Free) را انتخاب کنید.
3. فرم‌های اجباری زیر را تکمیل کنید (همه در منوی سمت چپ Play Console هستند):
   - **Store listing**: توضیح کوتاه و کامل برنامه، حداقل ۲ اسکرین‌شات، آیکون ۵۱۲×۵۱۲، گرافیک ویژه (Feature graphic) ۱۰۲۴×۵۰۰.
   - **Privacy Policy**: یک **URL واقعی و آنلاین** لازم دارید (نه فقط متن داخل برنامه). می‌توانید متن آماده در `lib/screens/about_screen.dart` (کلید ترجمهٔ `privacyPolicyBody`) را بردارید و در یک صفحهٔ ساده (مثلاً با GitHub Pages، Google Sites، یا هر هاست رایگان) منتشر کنید و لینکش را همین‌جا بدهید.
   - **App content**: پرسشنامهٔ رده‌بندی سنی (Content rating)، اعلام اینکه برنامه برای کودکان نیست (مگر خودتان بخواهید)، و فرم **Data safety** — چون از AdMob و ذخیرهٔ عکس استفاده می‌کنید، باید اعلام کنید که «شناسهٔ تبلیغاتی دستگاه» و «عکس‌ها» را (فقط به‌صورت محلی) استفاده می‌کنید.
   - **Target audience**: اگر مطمئن نیستید، «۱۸ به بالا» را انتخاب کنید تا الزامات اضافی مربوط به کودکان را نداشته باشید.
4. نسخهٔ (`app-release.aab`) را در بخش **Production > Create new release** آپلود کنید.
5. برنامه را برای بازبینی (Review) ارسال کنید — معمولاً چند ساعت تا چند روز طول می‌کشد.

### مرحلهٔ ۵ — ساخت حساب AdMob و اتصال به برنامه

1. به [admob.google.com](https://admob.google.com) بروید و با همان حساب گوگلی که در Play Console استفاده کردید وارد شوید.
2. روی **Apps > Add app** کلیک کنید، بگویید برنامه‌تان در گوگل پلی منتشر شده (یا هنوز نه، اگر قبل از انتشار می‌سازید)، و آن را به برنامهٔ Play Console‌تان وصل کنید (یا بعداً وصل کنید).
3. یک **App ID** به شما داده می‌شود (شبیه `ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY`) — این را باید در `android/app/src/main/AndroidManifest.xml` داخل تگ `<application>` قرار دهید:
   ```xml
   <meta-data
     android:name="com.google.android.gms.ads.APPLICATION_ID"
     android:value="ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY"/>
   ```
4. سپس دو **Ad unit** بسازید: یکی از نوع **Banner** و یکی از نوع **Interstitial**. هرکدام یک شناسهٔ جدا می‌دهد (شبیه `ca-app-pub-XXXX/YYYY`).
5. در فایل `lib/utils/ads.dart`، چهار شناسهٔ تستی گوگل را با شناسه‌های واقعی خودتان جایگزین کنید (دقت کنید Android و iOS شناسه‌های جدا دارند؛ اگر فقط اندروید می‌سازید همان دو مورد اندروید کافی است).

### مرحلهٔ ۶ — دریافت پول از تبلیغات (AdSense / پرداخت‌ها)

1. در پنل AdMob، به بخش **Payments** بروید.
2. اطلاعات مالیاتی (Tax info) را تکمیل کنید — گوگل از شما می‌خواهد فرم مالیاتی آمریکا (مثل W-8BEN برای افراد خارج آمریکا) را آنلاین پر کنید.
3. اطلاعات حساب بانکی یا Payoneer/Wise را برای واریز وارد کنید (بسته به کشورتان گزینه‌های مختلف نمایش داده می‌شود).
4. گوگل تا زمانی که درآمدتان به آستانهٔ پرداخت (معمولاً ۱۰۰ دلار) نرسد، پولی واریز نمی‌کند؛ بعد از آن، هر ماه به‌صورت خودکار واریز می‌شود.
5. **نکتهٔ مهم:** هرگز خودتان روی تبلیغات برنامهٔ خودتان کلیک نکنید یا از کسی نخواهید این کار را بکند — این باعث مسدود شدن دائمی حساب AdMob می‌شود.

### وضعیت فعلی تبلیغات در کد

- بنر تبلیغاتی پایین صفحهٔ Home نمایش داده می‌شود.
- یک تبلیغ تمام‌صفحه (Interstitial) بعد از ساخت هر تورنمنت جدید نمایش داده می‌شود (یک نقطهٔ طبیعی و غیرمزاحم).
- سیستم رضایت تبلیغات (Google UMP / GDPR) اضافه شده — برای کاربران اروپا/بریتانیا قبل از تبلیغات شخصی‌سازی‌شده رضایت می‌گیرد؛ این یکی از الزامات گوگل پلی است. کاربران می‌توانند از Settings > «تنظیمات حریم خصوصی تبلیغات» تصمیم خود را بعداً هم تغییر دهند.
- در ویندوز/وب/دسکتاپ هیچ تبلیغی بارگذاری نمی‌شود (چون AdMob فقط اندروید/iOS را پشتیبانی می‌کند) — این‌طور همچنان می‌توانید با `flutter run -d windows` برنامه را عادی تست کنید.

## چیزهای تازه در نسخهٔ ۲

1. **دو اسپلیش‌اسکرین پی‌هم**: ابتدا نام و لگوی برنامه به‌صورت بزرگ و واضح، سپس صفحهٔ «Developed by Naweed Rezayi»، هرکدام با انیمیشن محو/زوم، در نهایت وارد Home می‌شود.
2. **رمز عبور اختیاری برای هر تورنمنت** — هنگام ساخت تورنمنت می‌توانید آن را با رمز قفل کنید؛ باز کردن آن تورنمنت رمز را می‌خواهد.
3. **سرچ‌باکس در Home** برای دسترسی سریع به تورنمنت‌ها.
4. **فولدرهای نوع ورزش** (فوتبال، والیبال، بسکتبال، پهلوانی/کشتی، جودو، تکواندو، تنیس، کریکت، ای‌اسپورت، سایر) — هر تورنمنت هنگام ساخت به‌طور خودکار داخل فولدر ورزشی‌اش قرار می‌گیرد.
5. **گزینهٔ Next بعد از مرحلهٔ گروهی** — تا زمانی که همهٔ بازی‌های گروهی تمام نشوند غیرفعال است؛ به‌محض تمام‌شدن فعال می‌شود و جدول ناکوتی را می‌سازد.
6. **بدون محدودیت تعداد تیم** — چه در لیگ چه در ناکوتی؛ برای ثبت سریع صدها تیم، دکمهٔ «افزودن گروهی» یک اسم را در هر خط می‌گیرد و همه را یک‌جا اضافه می‌کند.
7. **سکوی قهرمانی به‌هم‌پیوسته** با نفر چهارم در کنار نفر سوم (ترتیب: دوم، اول، سوم، چهارم) + جدول عمودی نتایج.
8. **رنگ‌بندی جدول لیگ**: سه تیم برتر با سه شدت سبز (تیره تا کم‌رنگ) و سه تیم پایین جدول با سه شدت سرخ مشخص می‌شوند.
9. **زوم داخل صفحهٔ جدول ناکوتی** (Pinch to zoom / Pan) با InteractiveViewer.
10. **لگوی اختصاصی برنامه** به‌عنوان آیکون واقعی اپلیکیشن (`assets/icon/icon.png`) از طریق `flutter_launcher_icons`.
11. **ذخیره‌سازی پیشرفته با SQLite** (`sqflite`) به‌جای یک فایل JSON بزرگ — تیم‌ها، گروه‌ها و بازی‌ها در جدول‌های جداگانه و ایندکس‌شده ذخیره می‌شوند تا تورنمنت‌هایی با صدها تیم (و هزاران بازی تولیدشده) سریع بارگذاری و به‌روزرسانی شوند؛ هر ثبت نتیجه فقط همان ردیف را آپدیت می‌کند، نه کل داده را.

## راه‌اندازی (Setup)

```bash
# 1) پوشه‌های پلتفرم را بسازید (این پروژه فقط شامل lib/ و pubspec.yaml است)
flutter create .

# 2) وابستگی‌ها را نصب کنید
flutter pub get

# 3) آیکون اپلیکیشن را از روی assets/icon/icon.png تولید کنید
dart run flutter_launcher_icons

# 4) اجرا
flutter run
```

> نکته: چون `flutter create .` پوشه‌های android/ios را از نو می‌سازد، مطمئن شوید `pubspec.yaml` و `assets/icon/icon.png` موجود در این پروژه حفظ می‌شوند (این دستور معمولاً فقط فایل‌های native را اضافه می‌کند و pubspec.yaml شما را جایگزین نمی‌کند مگر تناقض داشته باشد).

## مجوزهای لازم برای آپلود عکس (image_picker)

**Android** — در `android/app/src/main/AndroidManifest.xml` داخل تگ `<manifest>`:
```xml
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES"/>
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" android:maxSdkVersion="32"/>
```

**iOS** — در `ios/Runner/Info.plist`:
```xml
<key>NSPhotoLibraryUsageDescription</key>
<string>برای انتخاب عکس تیم به دسترسی گالری نیاز است</string>
```

## 🤖 بخش یادگیری ماشین (برای پروپوزل)

**مدل:** سیستم رتبه‌بندی Elo با یادگیری آنلاین (`lib/ml/elo_rating_service.dart`)
- احتمال برد: `E = 1 / (1 + 10^((Rb − Ra)/400))`
- یادگیری بعد از هر بازی: `R += K · G · (S − E)` ( S نتیجه واقعی، G ضریب تفاضل گل، K نرخ یادگیری — برای تیم‌های کم‌داده بزرگ‌تر)
- احتمال مساوی: `P(draw) = d · 4E(1−E)` که `d` از خود داده‌ها (با هموارسازی لاپلاس) یاد گرفته می‌شود.
- **ارزیابی صادقانه (Prequential):** هر بازی قبل از یادگیری پیش‌بینی می‌شود، سپس دقت (Accuracy) و نمرهٔ Brier محاسبه می‌شود (در صفحهٔ «هوش مصنوعی» داخل تنظیمات).
- ذخیره‌سازی: جدول `rating_events` در SQLite؛ رتبه‌ها از روی تاریخچه بازسازی می‌شوند، بنابراین Undo/ویرایش هرگز مدل را خراب نمی‌کند. رتبه‌ها بین تورنمنت‌ها بر اساس نام تیم حفظ می‌شوند.
- نمایش: کارت «احتمال برد» در صفحهٔ ثبت نتیجه + صفحهٔ «هوش مصنوعی» (رتبهٔ تیم‌ها و کیفیت مدل).
- بدون هیچ وابستگی جدید (Dart خالص).

## v28 — تغییرات (فارسی)

1. **جدول ناکوت بعد از مرحلهٔ گروهی:** نفرات اول هر گروه مقابل نفرات دوم گروه‌های *دیگر* قرار می‌گیرند. اول و دومِ یک گروه همیشه در دو نیمهٔ مخالف (بلاک A و بلاک B) هستند و تا فینال به هم نمی‌رسند. اگر جدول به bye نیاز داشته باشد (مثلاً ۶ گروه)، bye به نفرات اول داده می‌شود؛ در این حالت‌ها ممکن است یک دیدار دور اول «اول مقابل اول» یا «دوم مقابل دوم» باشد (از لحاظ ریاضی اجتناب‌ناپذیر)، ولی هیچ‌وقت هم‌گروهی‌ها مقابل هم نیستند.
2. **افزودن تیم/بازیکن بعد از ساخت تورنمنت:** آیکون «افزودن تیم» در نوار بالای تورنمنت. لیگ: بازی‌های تیم جدید با بقیه اضافه می‌شود و نتایج قبلی حفظ می‌شود. مرحلهٔ گروهی (قبل از ساخت جدول حذفی): تیم به کوچک‌ترین گروه می‌پیوندد. حذفی مستقیم: تا قبل از ثبت اولین نتیجه. با دکمهٔ Undo قابل برگشت است.
3. **نمودار دایره‌ای** از بخش پیش‌بینی حذف شد (حلقهٔ درصد کارت اصلی هم با نوار خطی عوض شد).
4. DB تغییری نکرد (نسخهٔ ۴).
